节点：一个契约方块，且至少是能一定程度上嵌套/子节点的。包含五个内容：数据输入，输出，逻辑，验证和错误处理
- 核心在于体现一个意图。通常，这个意图会有已存在的函数——但是节点让意图永远成立
	- 比如读取一个文件。win确实有一个函数，但是如何用，如何用的好，如何把linux的也加进来，这就是一个称作”读取文件“的通用节点
- 更妙的是，节点具有约束和建议描述给ai。比如：读取文件可以具有”目前，文件应该位于某个目录，且关闭写入缓存“
- 节点具有流程图性质。
	- 显然的：
在需求级（业务功能：契约，文档，输入输出）和逻辑级（任务：局部状态，错误处理）我能100%理解。在实现级（函数某部分的算法）按需审计。
通常，其大小有两条限制：
- AI单步的合适上下文为其上限：五个内容和prompt加一起，不能超出大约30万token
- 合适的可理解性与逻辑独立性是其期望大小。
构建原则：
- 单职责
- 可测试性：简单的期望输入-输出字典必须能测试。

资源区：程序源代码级别的，且能在运行时动态添加的状态和资源的仓库。这必须能够按某种良好的方式排列，并且固化其空间划分方式。

实现：从零写的IDE
- **底层**：利用 [Monaco Editor](https://microsoft.github.io/monaco-editor/) 或直接调用 VS Code 的开源核心（VSCodium 背后那套）来处理语言解析、文件搜索等脏活。
- **表现层**：用 React 构建你梦想中的**节点图层**。
- **桥接层**：开发一个私有协议，让你的节点逻辑实时映射为磁盘上的代码文件。

type: "Header";

} 
interface Folder { 
type: "Folder"; 
name: string; 
isOpen: boolean; 
children: string[]; 
} 
interface File { 
type: "File"; 
name: string; 
extension: string; 
isDirty: boolean; 
} 
type ResponseMap = Record<string, Node>;
